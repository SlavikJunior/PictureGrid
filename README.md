# PictureGrid

Android-приложение для загрузки списка URL изображений, показа адаптивной галереи миниатюр и просмотра оригиналов в BottomSheet.

## Архитектура

Проект состоит из модулей:

- `:app` — composition root, навигация, тема.
- `:feature:gallery:api` / `:feature:gallery:impl` — контракт и реализация галереи.
- `:feature:viewer:api` / `:feature:viewer:impl` — контракт и реализация просмотра оригинала.
- `:core:common` — общие типы.
- `:core:network` — HTTP-клиент, ошибки, retry-классификация.
- `:core:images` — Coil `ImageLoader`, `ImageStorage`, загрузка оригиналов.
- `:core:navigation` — Router-обёртка над Navigation 3 и BottomSheet strategy.
- `:core:designsystem` — светлая и тёмная темы.

Архитектура feature-based: `api` не зависит от `impl`, `core` не зависит от конкретных feature-модулей. UI использует MVIKotlin с однонаправленным потоком данных.

## Запуск

Сборка debug APK:

```bash
./gradlew assembleDebug
```

Сборка release APK (R8 включён, подпись задаётся отдельно):

```bash
./gradlew assembleRelease
```

Проверка целостности зависимостей включена в строгом режиме: сборка падает,
если контрольная сумма артефакта отличается от зафиксированной в
`gradle/verification-metadata.xml`. Обновить снимок checksum-ов:

```bash
./gradlew --write-verification-metadata sha256 assembleDebug assembleRelease testDebugUnitTest
```

Бинарные артефакты, POM и Gradle Module Metadata проверяются строго. Файлы
`-sources.jar` и `-javadoc.jar` сознательно исключены из проверки: их скачивает
IDE при синхронизации проекта, чтобы открывать исходники и документацию в
навигации, но в сборку они не попадают. Без этого правила ручная синхронизация
в Android Studio падала бы с `Dependency verification failed` на 117
`-sources.jar` плагинов и их транзитивных зависимостей. Отдельно исключены
исходники и javadoc самого дистрибутива Gradle (`gradle:gradle`, файлы
`*-src.zip` и `*-javadoc.zip`) — IDE запрашивает их при синхронизации с того же
официального адреса `services.gradle.org`. Все правила описаны в
`<trusted-artifacts>` файла `gradle/verification-metadata.xml` и сохраняются при
обновлении снимка checksum-ов.

Установка на устройство/эмулятор:

```bash
./gradlew installDebug
```

Unit-тесты:

```bash
./gradlew testDebugUnitTest
```

Инструментальные тесты (нужно запущенное устройство или эмулятор):

```bash
./gradlew connectedDebugAndroidTest
```

Lint:

```bash
./gradlew lintDebug
```

Проверка зависимостей модулей:

```bash
./gradlew checkModuleDependencies
```

Screenshot-эталоны Roborazzi:

```bash
./gradlew verifyRoborazziDebug
```

## Поддерживаемые версии Android

- `minSdk = 26` (Android 8.0)
- `targetSdk = 37`
- `compileSdk = 37`

Диапазон подтверждён по фактической конфигурации проекта и совместимости используемых зависимостей.
Приложение проверено на API 26 (Android 8.0), API 30 (Android 11) и API 37.

Ограничение сервера из задания: `it-link.ru` принимает только TLS 1.3, а система
поддерживает TLS 1.3 начиная с Android 10 (API 29). На API 26–28 список с этого
сервера скачать нельзя — приложение показывает ошибку загрузки и использует
ранее сохранённый список, если он есть. Код приложения на API 26 проверен
полностью (загрузка изображений, просмотр оригинала, темы, адаптивная сетка).

## Кэширование

- Coil использует один общий `ImageLoader` с явными memory cache и disk cache.
- Превью Coil являются UI-кэшем и могут вытесняться политикой cache.
- Оригиналы сохраняются отдельно через `ImageStorage` в приватном каталоге приложения и читаются с диска при повторном открытии и после перезапуска.
- Каталог оригиналов ограничен 200 МиБ: при превышении удаляются самые старые файлы, свежий оригинал не удаляется.
- Повторно используемый оригинал проверяется по сигнатуре файла: повреждённый файл удаляется и загружается заново.
- Каталог оригиналов исключён из облачной копии и из переноса устройства; кэш Coil и так не попадает в бэкап.
- `images.txt` сохраняется в приватном каталоге приложения, а не в исходниках проекта.

## Retry и сеть
- Список загружается автоматически при запуске.
- При сетевой ошибке сохранённая копия не затирается.
- Экран следит за доступностью сети: когда сеть возвращается, список
  запрашивается заново и обновляется на экране, а не только в хранилище.
- Повторная синхронизация запускается через WorkManager с ограничением
  `NetworkType.CONNECTED`.
- Retry-политика определяется `NetworkError.isRetryable()`: временные сетевые ошибки, timeout, `EmptyBody`, HTTP 408/429/5xx повторяются; остальные 4xx не повторяются.
- Ошибки хранилища не считаются retryable.
- Объём ответа ограничен: 1 МиБ для текстового списка и 25 МиБ для оригинала (`NetworkLimits`). Превышение — ошибка `TooLarge` без автоматического повтора.
- HTTP-клиент работает со стандартным поведением OkHttp: автоматические редиректы и системный DNS, собственных политик допустимых адресов в проекте нет.

## Заглушки и ошибки загрузки

- Строка, которая не является HTTP(S)-URL, показывается заглушкой «Не ссылка».
- URL, ответ которого заведомо не является изображением (текстовый тип ответа
  либо неоднозначный тип без сигнатуры изображения), показывается заглушкой
  «Не изображение»: повторная загрузка не изменит содержимое.
- Остальные ошибки загрузки (недоступная сеть, HTTP-ошибка, данные, которые
  не декодируются) показывают действие «Повторить».

## Бонусные возможности

Реализованы все бонусные пункты задания:

- **Приближение щипком** в просмотрщике: масштаб 1–5, перетаскивание
  увеличенного изображения, двойное нажатие переключает исходный и
  увеличенный масштаб.
- **Перелистывание изображений**: горизонтальный свайп в просмотрщике
  переключает оригинал; рядом видны превью соседних изображений.
- **Полноэкранный режим**: нажатие по изображению или пустому месту
  скрывает панель действий, статус-бар и навигационную панель, лист
  раскрывается на весь экран. Повторное нажатие возвращает всё обратно.
  Системные панели можно временно вернуть свайпом от края экрана.
- **Поделиться и открыть в браузере**: ссылка на изображение отправляется
  другим приложениям или открывается в браузере.

Лист просмотра остаётся BottomSheet destination: скруглённые верхние углы
сохраняются и в полноэкранном режиме.

## Известные ограничения

- Инструментальные тесты требуют запущенного устройства/эмулятора. Espresso
  `3.7.0` (последняя стабильная версия) несовместим с Android 17: он обращается
  к удалённому в API 36+ методу `InputManager.getInstance()`. Поэтому
  инструментальные тесты запускаются на эмуляторе с API 30 (`pg_api30`),
  где они проходят; на API 37 падают с `NoSuchMethodException`.
- Debug-сборка разрешает cleartext-соединения только к `10.0.2.2` — адресу
  хоста из эмулятора. Настройка нужна для ручных проверок на версиях
  Android, где сервер из задания недоступен из-за TLS 1.3, и не действует
  в release-сборке (`app/src/debug`).
